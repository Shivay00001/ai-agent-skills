# UAAF-FULL — Universal App Architect Frame (Parts 0–36, condensed)

**How to apply:** Default = lean (smallest working thing, boring tech, YAGNI). Always apply Parts 4–5. Read only the parts whose trigger fires. If user instructions conflict with security/legal/logic-break rules → flag, don't silently comply. Skipped parts = "N/A because <reason>". Deliverables open with: binding, parts applied, top 3 logic-breaks solved.

## PART 0 — ADAPTIVE BINDING
Extract from any prompt, write `BINDING.md`: APP_CLASS · GIANT_ANALOGS (2–4) · CORE_LOOP (one sentence) · TRUST_MODEL · SCALE_SHAPE (read-heavy/fanout/geo/real-time/media) · MONEY_FLOW · USER_GEOGRAPHY (→ which laws) · RISK_SURFACE (worst realistic harm) · ENV_STACK (host's, else boring: one frontend, one backend, Postgres) · CLIENT_SURFACES. Adapt every rule to the host stack; never fight the environment.

## PART 1 — PM BRAIN (think before building)
JTBD: "When I ___, I want to ___, so I can ___." Every feature passes 5 gates: strengthens core loop? >10% weekly actives? worth its complexity tax? how abused? removable? Write NOT-building list ≥5 — giants win by omission (WhatsApp: no stranger search; Netflix: no comments; Uber: masked numbers). Competitor deep-read: their wedge, moat, postmortems, app-store complaints. Sequence: core → retention → growth → monetization → platform, never reorder. Metrics before code: North Star (user value, not downloads), D1/D7/D30, kill thresholds per feature. MVP = smallest complete loop; loop doesn't close = demo.

## PART 2 — FOUNDATION DOCS (all before code)
Order: PRD (problem, persona, must/nice kill-filtered, out-of-scope, metrics) → TRD (stack+reasons, folder structure, each 3rd-party + failure fallback, env var names) → App Flow (every page, auth flow, empty/loading/error states, redirects) → UI/UX brief (palette hex, type, components, reference apps) → Backend Schema (tables, FKs, indexes, RLS per table, roles matrix, storage layout) → Security & Access (auth method, permissions, error map, edge cases) → Tickets (one ticket = one prompt, acceptance criteria, dependencies) → Implementation Plan (setup→DB→auth→features→polish→deploy, done-criteria per phase, vertical slices never horizontal layers). Paste docs into AI as source of truth.

## PART 3 — SYSTEM DESIGN
8 irreversible decisions: UUIDv7 not sequential · UTC everywhere, server time wins · money = integer minor units + append-only double-entry ledger · soft-delete + hard-delete pipeline (retention matrix) · /v1 APIs additive-only · idempotency keys on every mutation · outbox event log day one · secrets in env + feature flags as kill switches.
Modular monolith first; extract services only on real triggers; Docker day one, K8s only with a team.
Scale shapes: messaging = gateway layer + per-user queues + sequence numbers + client-generated IDs + E2E if trust demands · feed = hybrid fanout (write for normals, read for celebrities), privacy computed at read time never cached stale · geo = H3/geohash index + strict trip state machine + safety features ARE product · media = async transcode pipeline + CDN-first + signed URLs.
Data: one source of truth, caches/indexes rebuildable projections; strong consistency for money/privacy, eventual for counters; cursor pagination; scale ladder indexes→replicas→cache→shard by immutable key; queues for async, consumers dedupe; backup ≠ backup until restore rehearsed.
Resilience: timeouts everywhere, retries w/ backoff+jitter+budgets, circuit breakers + written fallback per dependency, bulkheads, backpressure, degradation ladder (shed personalization before core loop).

## PART 4 — SECURITY (defense-in-depth, every layer)
TOP 4: (1) no secrets in frontend/repo, .env gitignored, secret scan in CI; (2) rate limits — auth 5/15min, API 60/min, LLM 10/min/user, uploads 5/min, 429+Retry-After, OTP endpoints capped (SMS-pumping); (3) server-side schema validation every route, parameterized queries only; (4) IDOR — ownership/role check on every object access, RLS, identity from session never request body, cross-tenant probes in CI.
Auth: bcrypt≥12/argon2id · JWT 15–60min, secret ≥32 chars · refresh in httpOnly cookie, rotation + reuse detection revokes family · established auth library · MFA at launch, mandatory for admin · recovery as strong as login, no enumeration (same response/timing).
Platform: HTTPS+HSTS · CORS whitelist never * · CSP, X-Frame-Options DENY, nosniff, remove X-Powered-By · uploads: MIME+magic bytes, size caps, UUID rename, bucket outside webroot, re-encode images, never executable · SSRF allow-list proxy · mass-assignment field allow-lists · errors generic to users + correlation ID, full server-side only · admin: separate origin, MFA, audit log · webhooks HMAC-signed + replay window · lockfiles + vuln scanning · debug off, DB not public.
LLM: keys server-side, prompt injection assumed, sanitize in/out, max_tokens, per-user budgets, usage logs.
Data: TLS 1.2+ + at-rest, field-level for sensitive, classify all fields, minimize (can't breach what you don't hold), retention purges automated, PII never in logs.
Abuse/T&S: report/block/mute in v1, velocity checks, device fingerprinting, moderation pipeline (auto → human queue → appeals), CSAM reporting non-optional, payout delays, promo farming assumed (device+payment dedup, caps, delayed rewards).
SecOps: STRIDE-lite per epic, append-only audit log (auth events, permission changes, admin actions), incident runbook BEFORE launch (severities, kill switches, forced-logout, key rotation, breach template), security review gates auth/payment/privacy changes.

## PART 5 — LOGIC BREAKS (hunt per flow: {flow, class, scenario, solution})
Races: double-spend/last-seat/username → atomic CAS + unique constraints, never check-then-act · retry-duplicate → idempotency keys end-to-end · stale reads → decision+write atomic · ordering → sequence numbers + state machines rejecting illegal transitions.
State machines: explicit per entity, server-validated, illegal transitions alerted; zombie states (paid-but-no-order) → saga/compensation + scheduled reconciliation; every wait has a deadline.
Boundaries: zero/max/negative/empty/emoji/RTL · DST, clock skew, expiry edges · 0- and 3-decimal currencies, one rounding rule, refund negatives · GPS drift/spoof, (0,0).
Incentives: "how do I farm this with 1,000 fake accounts?" → dedup, caps, delayed rewards · "one user consumes 10,000× median?" → quotas · marketplace bypass → masking + leak detection.
Dependencies: per-dependency written behavior when down/slow/garbage; partial failure default → reconciliation + honest pending UI; retry storms/stampedes → budgets, coalescing, jitter.
Success break: name first 3 bottlenecks at 100× + pre-planned mitigation.

## PART 6 — PRODUCTION GRADE
Observability: structured logs + correlation IDs, RED metrics p50/95/99, Sentry-class alerting on symptoms users feel, runbook per alert, SLOs with error budgets.
Delivery: CI gates (lint, types, tests, secret scan, migration lint), staging mirrors prod, expand→migrate→contract, canary + one-command rehearsed rollback, IaC, load-test 10× peak.
Client: loading/empty/error/offline states everywhere, offline-first where domain demands, tolerate N-versions-back, perf budgets, a11y + i18n architecture day one, crash reporting wired.
Operate: help center + scoped audited admin tools, on-call + blameless postmortems, per-feature cost + billing alarms, governed analytics schema.
DoD (12 points): happy path ✚ failure paths defined ✚ authz negative-tested ✚ validated ✚ rate-limited ✚ idempotent ✚ instrumented ✚ flag-wrapped ✚ UI states ✚ abuse-reviewed ✚ documented ✚ rollback plan. Eleven of twelve is not done.

## PART 7 — LAW & MONEY
Mindset: user data is radioactive; privacy is architecture. India DPDP ₹250cr + IT Act S85 pierces corporate veil (personal founder liability); fiduciary liable for processors.
Rules: India DPDP = explicit consent, minors <18 no tracking/ads + parental consent, breach → DPBI+users, rights access/correct/erase/nominate · GDPR = 72h breach, portability, legitimate-interest option · CCPA = notice + opt-out.
Build as features: data inventory + minimization · unbundled consent, one-click revoke, cookie banner before analytics · encryption + RBAC + automated retention purge · in-app rights portal wired to hard delete · vendor DPAs · breach playbook with clocks · takedown tooling ready · one named privacy owner.
Billing law: trial reminder ≥3 days before charge (logged, in-app too) · disclosure above buy button — price, frequency, trial, cancel — no dark patterns (FTC ~$51,744/violation) · click-to-cancel ≤2 taps same medium · IAP for digital goods, never embed third-party checkout in-app, Small Business 15% · descriptors clear, instant receipts, easy refunds, disputes <0.75% · EU VAT, India GST 18%, SCA; MoR (Paddle-class) simplifies global.

## PART 8 — LAUNCH
Web: OG 1200×630 absolute URL + debugger re-scrape · landing on root, app on subdomain · onboarding checklist ≤5 real actions to aha, server-tracked · analytics funnel + consent before tracking · sitemap (public only) + robots + Search Console · sweep: secrets, debug off, DB private, HTTPS, limits, CORS, RLS, generic errors.
Store: T&C + privacy pages required, data-safety honest · Play Console create (free→paid can't flip) · internal (≤100, instant) → closed (new accounts: 14 testers × 14 days) → production · signed .aab only · opt-in link, Gmail whitelist.

## PART 9 — EXECUTION LOOP
BIND → THINK → DOCUMENT → DESIGN → BREAK → BUILD (vertical slices, DoD each) → VERIFY (negative tests: wrong user, expired token, replay, concurrent dup, dependency down) → COMPLY & LAUNCH → OPERATE (flags, canary, measure, kill or scale) → GROW → HARDEN → RUN THE COMPANY.

## PART 10 — GROWTH
Pick native model: network/viral (invites = core UX, K 0.3–0.7) · content/SEO · paid (CAC<LTV/3) · sales-led. One primary first. SEO: SSR public pages, CWV in CI, programmatic pages with thin-content gates. ASO: keywords in title, first 2 screenshots = JTBD story, review prompt only after aha, <4.0 stars kills conversion. Referrals: two-sided, reward on referee ACTIVATION not signup, caps + device/payment dedup + delayed payout; optimize loop cycle time; every mechanic passes the farming hunt; growth never outruns T&S capacity.

## PART 11 — MONETIZATION
Wire money day one (ledger, entitlements), charge when retention proven — 10 paying strangers > 10k free. Value metric = THE pricing decision (seat/usage/flat/outcome — scales with customer value). 3 tiers + enterprise, middle anchored, annual ≈ 2 months free, PPP localization with VPN-arbitrage checks. Free strategy deliberate: trial / freemium (only if free users feed the loop or convert ≥2–4%) / reverse trial; grandfathering decided before first change. Entitlement service server-side, receipts validated server-side. Dunning recovers 20–40% involuntary churn (retries + emails + grace); measure voluntary vs involuntary separately. Subscription state machine + webhook reconciliation. Enterprise (flag-gated): SSO/SAML, SCIM, audit export, residency, SLA + status page, SOC2 path, DPAs, invoicing, seats. Metrics: MRR growth, ARPU, gross margin (LLM COGS in), cohort LTV, LTV:CAC≥3, payback<12mo, NRR>100%.

## PART 12 — MARKETING SOPs
Positioning first: "For [persona] who [need], [product] is the [category] that [benefit], unlike [alt] which [gap]" — 5 users can repeat it back or rewrite. Launch SOP: T-14 assets/landing/warm-up · T-7 creators/communities (give value, no drive-bys) · T-0 coordinated push, founder replies 24h · T+7 retro: which channel drove ACTIVATED users; double down, kill rest. Content: weekly pillar → 1:5 atomize, every piece = funnel stage + metric, UTM discipline. Channels: max 2 tests, budget + window + pass/kill metric BEFORE spend; one repeatable channel before diversifying. Lifecycle: welcome mirrors onboarding, behavior-triggered nudges, legal consent + unsubscribe. Proof: ask at success moments; case studies problem→numbers.

## PART 13 — ANALYTICS & EXPERIMENTS
Tracking plan as code: object_action names, versioned, PR-reviewed; pirate funnel instrumented day one; consent gates first. Don't A/B under ~1,000 weekly actives — ship opinionated, watch cohorts, 5-user interviews. When testing: one primary metric pre-declared, sample size upfront, no peeking, guardrails auto-halt, read full funnel. Flags = experiment system; sticky bucketing; append-only experiment log (hypothesis→result→decision) is the moat. Weekly metrics vs North Star; monthly cohort deep-dive; quarterly kill review — prune below thresholds.

## PART 14 — KPIs
North Star → input tree; every KPI has owner + target + lever, else it's trivia. Board: DAU/MAU ratio, activation, D1/D7/D30 (flattening = PMF), core-loop completions · MRR growth, ARPU, margin, NRR, LTV:CAC, payback, quick ratio >4 · burn multiple (<1.5 elite, >3 alarm), runway (raise at 6mo floor) · churn, disputes <0.75%, crash-free, p95, tickets/1k, incidents · class-specific: marketplace liquidity / messages/user/day / hours+completion / creation rate. Cohorts over blends; definitions frozen in dictionary; vanity ban (downloads, cumulative anything); red metric = owner + experiment or kill.

## PART 15 — COST
Know cost per core-loop action + per user by tier; tag everything; alarms 50/80/100% + anomaly (2× daily spike pages). Cloud: right-size (most run <20% util), autoscale down, staging sleeps · egress killer: CDN, compress, same-region, lifecycle hot→archive→delete · reserve only stable baseline (30–60%), spot for stateless · managed until premium > engineer-month; PaaS cheaper than DevOps hire. LLM: model-tier routing (biggest lever, often 10×), evals certify downgrades · exact+semantic caching, prompt caching, batch APIs 50% · trim prompts, cap max_tokens, RAG over stuffing · per-user token budgets tied to entitlements · cost per AI feature per user — COGS > tier ARPU = ladder down or kill. Monthly review: top-10 lines keep/optimize/kill; cost regressions block launches.

## PART 16 — DEVOPS
Golden path: clone→dev in 1 command; merge→staging auto; prod = 1 approval. Pipeline: PR (lint, types, unit, secret scan, dep audit, migration lint, preview env) → main (integration, build once + SBOM + scan, staging, smoke, core-loop E2E) → prod (canary 5→50→100 auto-rollback on SLO breach). IaC everything, no console clicking; ephemeral previews; synthetic staging data never prod PII; auto dependency PRs. Runbooks as one-command scripts (rotate keys, logout-all, DLQ replay, restore); monthly restore drill; deploy SHA visible. DORA: deploy frequency, lead time <1d, change-failure <15%, MTTR <1h.

## PART 17 — AI AGENT ORCHESTRATION
Roles: Architect (binding+docs+ADRs, no feature code) · Builders (one vertical slice each, ticket+criteria+scoped files only) · Security reviewer (adversarial, every diff) · Logic-breaker (Part 5 hunt + negative tests) · Test agent · Integrator (only merge authority) · Ops (postmortems→tickets). Minimum separation: builder ≠ reviewer ≠ security. Laws: context rationed not dumped · handoffs are artifacts not chat · interfaces frozen BEFORE parallel fan-out · no agent merges own work, CI applies zero exceptions · disagreements → architect, decided against frame · human checkpoints: plan approval, auth/payment/privacy diffs, prod deploy. Memory = repo: BINDING.md + ADRs + ticket updates; fresh sessions re-bind from files, never stale chat. Agent charters versioned in /agents/, measured on rework rate not volume.

## PART 18 — AI CODING GUARDRAILS
Same rules file as CLAUDE.md / AGENTS.md / GEMINI.md / .cursorrules. DO-NOT: invent endpoints/tables/env vars · add deps without approval (verify package exists — typosquat/hallucination risk) · touch auth/payments/PII without flagging · weaken validation/tests to pass · hardcode secrets · delete tests to green · swallow errors · drive-by refactors · claim "tested" without proof · guess ambiguity (mark DECISION-NEEDED, stop). Task shaping: small tickets → small diffs (>300 lines unreviewable); every prompt = ticket + criteria + file scope + doc excerpt; response states changed/not-changed/assumptions/verify-how; plan-then-execute for non-trivial; fix the prompt and regenerate, don't iterate on bad structure. Verify: pipeline gates → AI-typical property checks (negative, IDOR, concurrency, boundaries — AI writes happy paths) → human eyes on authz/money/state machines. AI code gets MORE scrutiny in critical paths — it looks cleaner while being wrong. Traps: confident nonexistence, convention drift, context truncation (constraints from 40 messages ago), sycophantic agreement, test theater.

## PART 19 — FUNDRAISING
Raise only when the machine is proven and capital accelerates it (LTV:CAC≥3, capital-constrained) — WhatsApp ran ~55 engineers. Dataroom assembles from artifacts: KPI history + dictionary, security posture, compliance file (DPDP/GDPR now diligence items), clean cap table + IP assignments (AI-era provenance probed), experiment log, unit economics. Narrative: problem → wedge → traction (flattening retention) → why-now → compounding moat → unit economics → funds tied to named KPI targets; slope beats intercepts. Stages: pre-seed = team+insight+prototype · seed = activation + retention signal or 3–5 paying logos · A = repeatable channel + NRR + sane burn. Start at 8–9 months runway; batch meetings 2–3 weeks; monthly updates before you need money; red flags: participating preferred, >1× liquidation, full ratchet.

## PART 20 — API GOVERNANCE
Contract-first: OpenAPI/SDL in repo is truth, clients/SDKs generated, drift fails CI. Style decided once + linted: plural resources, one casing, one error envelope {code, message, correlationId}, cursor pagination, standard idempotency + rate headers. Additive in-version; breaking = new version; Deprecation/Sunset headers; per-client telemetry makes sunsets data-driven. GraphQL: persisted queries in prod, depth/complexity limits, dataloaders. SDK examples run in CI.

## PART 21 — DATABASE EVOLUTION
Zero-downtime shape: expand → batched throttled backfill → dual-read verify → contract; never rename in place. Online schema tools for big tables; every migration declares lock budget or CI rejects. Engine upgrades blue-green: replica → lag-zero + checksums → cutover, rehearsed on prod-clone. Shard moves: dual-write + reconciliation differ, cutover behind flag, rollback = flag flip. Rollback matrix: auto-revertible / script-revertible / point-of-no-return (sign-off + snapshot + forward-fix plan).

## PART 22 — CACHING & SEARCH
Every cache entry has ONE owner; layer map written (browser→CDN→edge→app→DB); TTLs jittered. Cache-aside default; write-through for read-after-write truth; never cache authz/privacy decisions. Invalidation event-driven off outbox; CDN stale-while-revalidate; pre-warm before known spikes. Stampede: coalescing + early recompute. Search = rebuildable projection off event stream; reindex-into-alias flips; typo tolerance + synonyms; ranking tuned offline first; vector/hybrid where semantic; zero-result queries feed roadmap. Search respects ACLs at query time — snippet leaks are IDOR.

## PART 23 — NOTIFICATIONS & JOBS
One service, all channels (email/SMS/WhatsApp/push/in-app/webhooks); product emits intent events. Per-user preferences + category opt-outs, quiet hours by timezone, priority queues (transactional > security > product > marketing — marketing never delays OTP), dedup keys, digest collapse, daily caps. Provider failover; bounces → suppression; receipts into events. Jobs: cron registry (owner, timeout, alert-on-miss), jittered starts; long jobs checkpoint + heartbeat; workflows = state machines with per-step retry/compensation; workers idempotent, per-queue caps, DLQ + replay + growth alert.

## PART 24 — MULTI-TENANCY & EXTENSIBILITY
Model chosen by isolation vs cost (pooled tenant_id / schema / db per tenant), recorded in ADR; every query tenant-scoped by construction; cross-tenant probes in CI — multi-tenant IDOR ends B2B companies. Per-tenant quotas (rate/storage/jobs), enterprise per-tenant keys, tenant flags. Lifecycle: templated provision, migrate via dual-write, full export (= portability), per-tenant backup/restore, offboard → evidenced hard delete. Metering → entitlements + invoices; explicit overage policy. Plugins: stable public hooks only, sandboxed (declared permissions, resource limits, kill switch), marketplace = review + signing + revocation; ecosystem abuse becomes YOUR abuse surface.

## PART 25 — RELIABILITY (SRE)
SLIs at user boundary per journey; SLOs from user tolerance; error budget = 1−SLO spent by incidents AND launches — burned budget auto-freezes features. Page on burn RATE; every page has a runbook. Load tests scheduled; capacity alarms at 70% of known ceilings. Chaos: game days → staging faults → controlled prod, verify claimed fallbacks. Incidents: SEV1/2/3 defined cold (ambiguity resolves UP), IC/ops/comms roles separated, rotation + auto-escalation, live timeline, blameless postmortem ≤5 days with plural contributing factors + owned dated actions tracked to closure.

## PART 26 — CONTINUITY & DR
RTO/RPO per system decided by BUSINESS → picks tier: backup-restore / warm standby / active-active. 3-2-1 backups, one copy OFF primary cloud account (account lockout IS a disaster); restore drills timed against RTO; runbooks live outside blast radius. Map shared fate (region/account/provider/CA/auth); SPOFs accepted in writing or engineered away. Crisis comms: pre-approved templates (status, in-app, breach with legal clocks, press), named spokesperson, status page hosted OUTSIDE own infra, committed update cadence. Key-person: every critical system ≥2 humans or 1 + runbook; break-glass vault; playbooks for top-5 vendor failures.

## PART 27 — AI EVAL & GOVERNANCE (AI in product)
No eval, no ship: golden dataset per feature (representative + hard + adversarial + regression from prod failures), versioned; scoring exact/rubric/human by stakes. Eval gate in CI: prompt/model/param changes must beat or consciously trade current score. 4-axis scorecard: quality (accuracy/hallucination/refusal), latency p95, cost per task, safety violations. Prompts are code (versioned, reviewed); every response logs {prompt_version, model, params}; upgrades: eval → shadow → canary → full, flag rollback; provider deprecations tracked. Actions classified green (auto) / yellow (sampled review) / red (money, moderation, medical/legal → human approves BEFORE effect); confidence routes to humans; degraded mode defined — never silent garbage. Written safety policy per surface; append-only audit (input, output, versions, reviewer); user feedback → regression sets, with consent, PII scrubbed, tenant-isolated.

## PART 28 — RELEASE & CONFIG
Deploy ≠ release: deploy dark continuously; release = flag flip staged 1→10→50→100 with guardrails; release rollback = seconds. Mobile: release train (misses catch next), rings internal dogfood → beta → staged → GA; hotfix lane SEV1/2 only + retro; flags let you kill features without store review; freeze windows respected. Config 5 classes (build / env / runtime-remote / tenant / regional), each with owner + audit; config changes ARE deploys (reviewed, versioned, rollbackable); schema-validate at load; safe default if flag service down; dead-flag cleanup cadence.

## PART 29 — ADR, RTM, DOCS & DESIGN SYSTEM
ADRs (/docs/adr): context → options → decision → consequences → status; append-only, superseded not edited; "why Postgres/UUIDv7/queue X" answered forever; agents must read before proposing; frame deviations are ADRs too. RTM: REQ-ID → PRD → design → code PRs → tests → monitors, generated from conventions (IDs in tickets/tests/alerts); catches untested promises, zombie scope, unmonitored features. Docs: owner + review-by date; live next to code, change in same PR; archive never delete; wrong doc worse than none. Design system: tokens single source exported to platforms; versioned component library — every component ships loading/skeleton/empty/error/disabled + a11y baked; icon system incl. app-icon kit (adaptive layers, favicon, splash, store) from one master; motion tokens + reduced-motion.

## PART 30 — SUPPLY CHAIN, DATA GOV, A11Y
SBOM per build stored per release; artifacts signed, provenance verified; dep intake: registry-exists, typosquat check, maintained, license OK; lockfiles + digest pins; CI is production (hash-pin actions, scoped tokens, alert on workflow changes); containers minimal non-root, no :latest. Data governance: catalog with owner + classification; lineage where money/PII flows; master data one golden record; quality rules as code alerting; warehouse/BI PII-masked by default; wrong-data incidents run the incident process. A11y = WCAG 2.1 AA gate: keyboard-complete + visible focus + modal traps; semantic HTML, labels, live regions, real screen-reader audit per release; contrast ≥4.5:1 in tokens, 200% text scale, reduced-motion, plain-language errors; captions/transcripts/alt; per-component at birth, not per-app at lawsuit.

## PART 31 — CUSTOMER SUCCESS
Help center from real ticket themes (deflect 80%); one queue of record, SLAs by tier (enterprise = contract terms, alert pre-breach); support admin scoped + audited, impersonation with consent, money powers two-person. Tickets-per-feature = engineering quality metric, weekly review; known-issue banners during incidents. Onboarding: self-serve checklist + emails; enterprise kickoff + agreed success criteria + 30/60/90. Churn: health score (usage+sentiment+billing), playbooks BEFORE renewal, coded exit interviews, reason-timed win-backs. NPS quarterly + CSAT per interaction, capped; detractors get humans in 48h, promoters get the review/referral ask.

## PART 32 — LEGAL OPS
Templates reviewed once (MSA, NDA, DPA, contractor); signed-doc repo + renewal calendar with alerts; redlines actually reviewed. IP assignment from EVERY contributor now — one missing contractor signature clouds the codebase at diligence; correct contractor/employee classification; ESOP matches cap table. Vendors: DPAs, SLAs aligned to your RTO, exit + data-return clauses. Trademark search BEFORE naming; file in core markets; secure domains/handles at naming; patents = ADR'd decision (usually trade secrets + speed). OSS policy: allow MIT/Apache/BSD, review LGPL/MPL, deny AGPL in proprietary SaaS; ship attribution; scrub history before open-sourcing. Quarterly regulatory watch, one owner.

## PART 33 — HR & HIRING
Pipeline as funnel with time-in-stage; scorecard BEFORE the role opens; every hire = complexity tax. Structured interviews: same questions, rubrics, written feedback before debrief (unstructured measures charisma); paid work-samples; references actually called. Onboarding: day-1 ready (access via RBAC, onboarding doc), week-1 ship, 30/60/90 written, buddy; newest joiner audits the doc. Weekly 1:1s (blockers+growth); quarterly written reviews — feedback that's news = management failure; underperformance → early written plan, contemporaneous docs. Comp bands + equity bands (4y/1y) BEFORE negotiation; annual market review. Role-clarity doc; single-person-risk map → cross-training; culture = worst behavior tolerated.

## PART 34 — DATA ENGINEERING
Analysts never query prod: CDC/event stream → warehouse/lakehouse. ELT with versioned tested transforms; data contracts at producer boundaries (schema+semantics+SLA, break loud in CI); pipelines idempotent by partition; backfills = governed checkpointed jobs. Raw → staging → marts; semantic layer = executable metrics dictionary — one definition of "active user"/"revenue" everywhere. Lakehouse for raw (lifecycle tiers), warehouse hot; erasure propagates to derived stores + training sets (the classic compliance miss). ML: feature store offline=online (skew kills), datasets versioned + reproducible, PII consent-governed + scrubbed, model lineage, deploy via eval→shadow→canary.

## PART 35 — I18N & LOCALIZATION
ICU strings only (plurals/gender), no concatenation; locale-aware dates/numbers/names/addresses/phones; RTL first-class; +35% text expansion room; locale in profile. Currency: display ≠ settlement, both stored, minor units incl. 0/3-decimal; one timestamped FX feed, rate on invoice; PPP pricing with native endings (₹199 not ₹184.37); refunds in original currency at original rate. Tax engine/MoR per jurisdiction; inclusive display in EU, exclusive US; local invoice formats. Regional config: residency routing, per-market feature gates, age thresholds, localized moderation, grievance-officer obligations. TMS pipeline versioned like code + glossary/tone per language; pseudo-localization in CI; market launch = listing + help + legal + local payment methods; per-locale funnels — traffic without activation = localization bug.

## PART 36 — FINANCE
Separate banking day 0; accounting system reconciled three ways monthly: books ↔ internal ledger ↔ processor payouts. Accrual once subscriptions exist; deferred revenue is a liability. Read all three statements monthly — cash flow is the killer (profit ≠ cash: prepays, refunds, holds). Budget + monthly variance; rolling 12-month forecast from KPI model, bear case sets hiring; <12mo runway → 13-week cash forecast weekly; quarterly vendor-spend audit (zombie SaaS seats). Controls: approval thresholds, payer ≠ reconciler, out-of-band verification of bank-change requests (invoice fraud epidemic), card limits + receipts. Tax calendar with owners (income, GST/VAT, payroll, TDS); nexus reviewed as geography grows; accountant BEFORE the first complex filing.
